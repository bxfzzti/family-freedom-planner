# 输出协议

## 默认：一页决策摘要

先说明现在能判断到哪一步。数据不足时写“暂不能定方向”，不填造数字；有可靠测算后再给条件化倾向。默认约500—800字以内，简单问题更短，用户要求详细时展开。

1. **当前判断与成立条件**：哪一方案更贴近目标；缺什么可能改变结论。
2. **方案对比**：用小表比较真实可行方案，包括所需现金、行动后剩余可动用资产、年现金流、主要压力情景缺口，以及生活改善和代价。所有方案使用相同周期、单位和收入支出口径。未算出写未测算，不用0代替。
3. **暂停线与失效条件**：可核对的金额、时间或事件；区分用户底线和模型暂定假设。
4. **下一步**：优先列一至三件可以执行或核实的事。新信息到来后何时重新评估。

不强制把每段都输出为标题。仅首次信息收集时遵循 intent-to-intake.md，不机械输出空表。先说明已知矛盾，再问最多三个缺项。

现金“能撑多久”必须交代定义：全部收入中断下的必要支出覆盖，还是压力情景净缺口覆盖；有正结余时不能写“无限安全”。资产范围与重复扣减必须可追溯。

## 完整规划：内部完成检查与按需附录

完整测算仍覆盖：家庭底盘、未来关键时间点、最多三个核心矛盾、可行方案、关键经济计算、正常/压力/严重情景、五维自由度、安全线与红线、3个月/12个月/3年行动、失效条件和重新评估触发器。摘要短不等于省略适用计算、执行或完整性检查。

方案分别交代适用条件、经济结果、换来的生活改善、牺牲的东西、撤回成本和失效条件。普通用户可用“优先考虑 / 条件满足后可考虑 / 风险较高”，内部保留 RECOMMENDED / ACCEPTABLE / HIGH_RISK。

只有在数值与适用门禁通过后才给确定性判断。结论强度：

- Strong：确定性数学支持明确，关键口径已确认。
- Moderate：已验证范围内差异明显，仍有有限不确定性。
- Conditional：依赖明确列出的条件；不得写成必然。
- Exploratory：关键变量不足，仅界定问题和待验证条件。

## 用户更新数据

默认只回答“什么变了 → 哪些数字受影响 → 原建议如何改 → 下一步”。保留未变的约束，不重发完整问诊。发现旧计算错误时明确更正，不把错误包装成用户改变了想法。
