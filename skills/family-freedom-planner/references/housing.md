# 房产决策与置换

## 禁止只看旧房涨跌

如果用户最终会置换，核心指标是：

`置换价差 = 目标房成交价 - 旧房成交价`

更完整：

`置换资金缺口 = 目标房总现金需求 - 旧房出售净回款`

目标房和旧房可能不同步。

至少测试：

- 旧房 -10%，目标房 -10%
- 旧房 -10%，目标房 -2%
- 旧房不变，目标房 +5%
- 旧房 +5%，目标房 +5%

## 现在卖 + 租房等待

简化公式：

`卖房净回款 = 售价 - 剩余贷款 - 交易成本`

`租金成本 = 月租 × 12 × 等待年数`

`卖房资金收益 = 净回款 × ((1+低风险收益率)^年数 - 1)`

`避免的旧房利息 ≈ 剩余贷款 × 贷款利率 × 年数`

`等待净成本 = 租金 - 资金收益 - 避免利息 + 搬家等摩擦成本`

`旧房盈亏平衡跌幅 ≈ 等待净成本 / 当前房价`

这不是房价预测，只是“提前卖出的保险成本”。

使用 `scripts/family_freedom_engine.py sell-rent ...` 可做确定性计算。

## 买房必须看买后流动性

不要只问“银行能贷多少”。

必须展示：

- 首付/自有资金；
- 税费、装修、搬家；
- 买后金融资产；
- 应急金；
- 未来24个月确定资本支出；
- 高收入失效后的住房现金流。

若买后金融资产接近0，默认高风险，即使月供很低。

## 终局住房

如果用户明确买后长期不卖：

- 不把该住房视为职业转型备用现金；
- 提高买后流动资产要求；
- 提高融资失败安全边际。

## 方案排序

常见方案：

- 继续持有；
- 现在卖、租住等待；
- 直接置换；
- 先解决学区，改善后置；
- 降低终局房总价。

输出必须说明“换来了什么”和“牺牲了什么”，不能只用财务收益排序。

v1.4多方案结果为 `results.options[]`，每项使用与OPTIONS_BUILD一致的唯一 `option_id`，并保留行动前流动资产、现金支出、卖房净流入、行动后流动资产、旧房价、目标房价和置换价差。控制器逐项复算，任何一项缺失或不一致都会阻止无条件结论。
